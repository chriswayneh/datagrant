# DataGrant v0.8.0 release notes

DataGrant v0.8.0 adds the PCI DSS support pack.

## What changed

- **Payment card data policy.** Use `card_data` to tag primary account numbers (PAN), CVV, and track data. Tagged PAN can use `pan`, `redact`, or `null`. DataGrant rejects tagged CVV and track data in grant projections and rejects tagged card data in row filters. [Policy reference](../policy.md)
- **PAN display masking.** Postgres, Snowflake, and BigQuery grant views show at most the first six and last four digits. Malformed values are redacted and null values stay null.
- **Fictional PCI DSS policy.** The sample uses OIDC, separate requester and approver groups, and short grant and approval windows. [Sample policy](../../examples/policies/pci.yaml)
- **Signed receipt reports.** Run `datagrant receipts report --pubkey HEX_OR_FILE` for Markdown or add `--json`. Use `--expect-head` with an independently recorded hash to check for missing recent receipts. Reports summarize grant events for access reviews. [CLI reference](../cli.md)
- **Control mapping.** The PCI DSS v4.0.1 guide maps these features to selected requirements and shows how to reconcile receipts with warehouse permissions and query logs. [PCI DSS guide](../compliance/pci.md)

## Upgrade and verification

Policies without card-data tags retain their existing rules. To adopt the pack, classify all source columns and aliases in scope and check the policy with `datagrant policy check`.

Postgres masking is covered by an integration test. Snowflake and BigQuery coverage verifies generated SQL. Those two engines still need live validation for this pack.
