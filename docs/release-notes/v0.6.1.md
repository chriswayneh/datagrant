# datagrant v0.6.1

> Ready, release pending. Not tagged or published yet. The latest published release remains [v0.6.0](https://github.com/chriswayneh/datagrant/releases/tag/v0.6.0).

**Patch for the v0.6.0 Snowflake setup that called `SHA2_HMAC`.**

## Fixes

- **v0.6.0 Snowflake setup called `SHA2_HMAC`, which Snowflake lacks**, so `ensure-state` / hash failed. Setup now creates a secure Python 3.12 UDF that uses the standard-library `hmac` (`hmac.digest`). NULL stays NULL. The hash key column is BINARY. ([#61](https://github.com/chriswayneh/datagrant/pull/61))
- **This fix is verified by CI and SQL checks only. There is no live Snowflake smoke test.**

## Upgrading

1. There is no hash-output break for Postgres in this version. Snowflake hashes remain not designed to be joinable with Postgres hashes (different HMAC output encoding). The v0.2.0 per-dataset `hash_scope` change from v0.1.0 still applies if you are coming from 0.1.x; see [v0.2.0 notes](v0.2.0.md).
2. Install from source (`pip install .` in this checkout). For Snowflake, `pip install '.[snowflake]'`. datagrant is not on PyPI. A v0.6.1 tag is not published yet.
3. Existing keys, policies, receipt logs and Postgres state schemas keep working. Re-run Snowflake `ensure-state` / `--apply` setup so the Python HMAC UDF replaces the v0.6.0 `SHA2_HMAC` call.
4. Everything else in [v0.6.0](v0.6.0.md) is unchanged.

## Requirements

Python 3.11+, Postgres (CI tests 16), and `pgcrypto` for Postgres hash masks. Snowflake is an optional extra (`snowflake-connector-python>=4.7.3,<6`). No live Snowflake in CI.

## Known limits

The [v0.6.0 known limits](v0.6.0.md#known-limits) still apply. This patch does not add a live Snowflake smoke test.
