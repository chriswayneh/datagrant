# datagrant v0.3.0

> Released 2026-11-07: [v0.3.0 on GitHub](https://github.com/chriswayneh/datagrant/releases/tag/v0.3.0).

**Optional OIDC identity for datagrant's just-in-time, masked Postgres access.**

## Highlights

- **Optional OIDC identity.** `policy.identity.mode: oidc` verifies a compact ID token on every `request` and `approve` (RS256 / ES256 / EdDSA, exact `iss`, audience, `exp`, `iat` within `max_token_age`). Default `mode: local` (and omitted `identity`) still uses the OS user or `--as-user`.
  - Token input is `--oidc-token-file` (0600, no symlinks, beats env) or `$DATAGRANT_OIDC_TOKEN`. There is no `--oidc-token` flag.
  - In `oidc` mode `--as-user` is refused. IdP groups grant nothing unless `identity.group_map` translates them. `allowed_groups` is an admission gate only.
  - Two-person `approve` checks identity-mode parity, matching `iss` / `username_claim`, and both the display name and `(iss, sub)`.
  - Receipts stay version 1 with additive `identity` and `approver_identities` (`iss`, `sub`, `token_sha256`). The raw token is never stored. `revoke` and `sweep` still take no identity.
- Walkthrough: [OIDC request and approve demo](../demo-oidc.md) (synthetic tokens; `make demo` stays local identity).

## Fixes

- CLI error redaction no longer globally replaces a DSN password shorter than 4 characters, which mangled diagnostics (password `er` turned `server error` into `s***v*** ***ror`). `user:pass@` and `password=` forms are still redacted at every length.

## Upgrading

1. There is no hash-output break in this version. The v0.2.0 per-dataset `hash_scope` change from v0.1.0 still applies if you are coming from 0.1.x; see [v0.2.0 notes](v0.2.0.md).
2. Install the new version from source (`pip install .` in a checkout of the v0.3.0 tag). datagrant is not on PyPI.
3. Existing keys, policies, receipt logs and state schemas keep working. Policies that omit `identity`, or set `mode: local`, behave as in v0.2.0.
4. Optional: add `policy.identity` with `mode: oidc`. See [operations](../operations.md#oidc-identity-v030), the [policy identity block](../policy.md#identity) and the [CLI reference](../cli.md#oidc-identity). Check with `datagrant policy check`.
5. The short-password redaction fix is automatic. Use an admin password of 4 or more characters if you need the password string itself stripped from leftover diagnostic text.

## Requirements

Python 3.11+, Postgres (CI tests 16), and `pgcrypto` for hash masks. No new dependencies.

## Known limits

- Local identity is not authentication: `--as-user` and OS user names are not verified.
- OIDC is a CLI boundary, not a database boundary. Anyone who holds the admin DSN can still bypass datagrant.
- Bearer ID tokens can be replayed until `exp` and `max_token_age`. There is no DPoP or live IdP session revocation.
- A revoked IdP signing key remains accepted until `jwks_cache_ttl` (default `5m`).
- Unmapped IdP groups grant nothing, even when the name matches a policy group.
- `http://` localhost issuers need `DATAGRANT_OIDC_ALLOW_INSECURE_LOCALHOST=1` and are for tests only.
- Short DSN passwords (1-3 characters) can still appear as bare substrings in messages; URI and `password=` forms are always stripped.
- Hashes are still linkable within one scope, and anyone with the hash key file can recompute them.
- A grantee knows every visible row matched the filter, even on a hidden filter column.
- NULL stays NULL under `partial` and `hash`; `partial` keeps the length.
- Receipts not yet delivered to the sink can't be checked off-host; in `best-effort` mode they can be deleted before `receipts push` runs. The sink is only as trustworthy as its receiver.
- The sink token lives in the environment.
- On Windows, the receipt log, the file sink and outbox flushes aren't locked; run one writer at a time.
- Symlinks are refused for the final path component of key, log, cursor and sink files, but parent directories are followed.
- Disable statement logging for the admin role.
