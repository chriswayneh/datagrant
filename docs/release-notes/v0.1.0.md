# datagrant v0.1.0

> Released 2026-11-02: [v0.1.0 on GitHub](https://github.com/chriswayneh/datagrant/releases/tag/v0.1.0).

**datagrant gives developers just-in-time, expiring, masked access to PHI/PII in Postgres, and leaves a signed receipt for every grant and revoke.**

## Highlights

- **Ask narrowly, get narrowly.** Request specific columns, an allowed row filter, a duration and a purpose. A YAML policy decides, denies by default, and says why.
- **Masked by construction.** The grantee reads a `security_barrier` view with `redact`, `null`, `partial` or keyed-HMAC `hash` masks, never the base table.
- **Access that ends.** Each grant is a temporary LOGIN role with `VALID UNTIL`. `revoke` and a scheduled `sweep` lock the role out, kill open sessions, and drop it.
- **Evidence you can check.** Receipts are ed25519-signed and hash-chained. `datagrant receipts verify` finds the first altered entry, and `--expect-head` catches truncation. No receipt, no access.
- **Two-person mode.** With `approval: two-person`, a request waits until someone in an approver group approves it. Only a SCRAM verifier is stored.
- **Safe by default.** Every changing command is a dry run until you pass `--apply`. Exit codes are 0–4 and suit automation.
- **Try it in a minute.** `make demo` runs the whole flow against a throwaway, localhost-only Postgres and tears it down.

## Requirements

Python 3.11+, Postgres (CI tests 16), and `pgcrypto` for hash masks.

## Known limits

Identity is not authentication (`--as-user` and OS user names aren't verified). Row-filter columns are visible. Masks reveal NULLs and lengths. Hashes are linkable across grants. Tail truncation needs `--expect-head`. Windows receipt logs need a single writer. Disable statement logging for the admin role. Details: [docs/security.md](../security.md).
